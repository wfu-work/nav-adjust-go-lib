# nav-adjust-go-lib 站网平差解决方案设计说明

> 面向对象：项目业主、测量技术人员、系统集成方和成果审核人员
>
> 文档版本：客户版
> 核心主题：项目定位、业务能力、处理流程、质量保障和交付边界

## 1. 摘要

`nav-adjust-go-lib` 是一套面向 GNSS 相对定位成果的三维 ENU 站网平差能力。

它把多个站点之间的相对坐标结果、各结果的精度信息和必要的控制点信息，统一整理为一个整体一致的站网成果。系统不仅给出每个站点的最终坐标，还会说明每条观测在平差中的表现、成果精度以及是否存在异常或薄弱环节。

可以把它理解为：

> 将“许多条带有误差、精度不同、可能不完全闭合的相对测量结果”，转换为“一套统一基准、整体协调、质量可检查的站点成果”。

### 1.1 业务价值

- **统一成果**：多条基线共同参与计算，减少逐条使用造成的坐标不一致；
- **充分利用精度**：精度高的观测影响更大，精度低的观测影响更小；
- **发现问题**：通过残差、冗余度和整体检验定位可疑观测；
- **兼容不同基准**：支持固定控制点、带精度的控制点和纯相对自由网；
- **适应规模变化**：从小型控制网到大型稀疏站网均有对应的计算策略；
- **便于成果审核**：输出坐标、精度、残差和质量结论，支持复核和追溯。

### 1.2 在整体业务链中的位置

```text
GNSS 原始观测 / RTK 或其他基线解算
                │
                ▼
     坐标系统一、数据整理、精度评定
                │
                ▼
      nav-adjust-go-lib 站网平差
                │
                ├─ 站点统一坐标
                ├─ 平差后基线
                ├─ 坐标与观测精度
                ├─ 残差和异常提示
                └─ 整体质量结论
                │
                ▼
       成果展示、审核、入库或业务应用
```

该项目处于“基线或相对定位结果已经得到”之后。它不是原始 GNSS 观测解算器，也不替代 RTK、PPP 或坐标转换系统。

## 2. 产品定位与适用客户

### 2.1 适合解决的问题

该方案适合以下类型的业务：

- 一个项目中有多个站点，需要形成统一的站网坐标；
- 同一站网包含多条闭合或交叉基线，单条结果之间存在轻微不一致；
- 不同接收机、不同观测时段或不同解算策略产生的结果精度不同；
- 需要使用固定控制站或带不确定度的外部坐标；
- 没有外部控制点，但仍需要得到内部相对坐标；
- 需要自动发现粗差、弱观测或随机模型不合理的情况；
- 站点规模较大，普通一次性矩阵计算的内存压力较高。

### 2.2 不属于本方案的工作

| 事项 | 责任归属 |
| --- | --- |
| RINEX、RTCM、接收机原始数据解析 | 上游数据处理或 GNSS 解算系统 |
| 卫星位置、钟差、电离层、对流层和模糊度处理 | RTK、PPP 或其他定位引擎 |
| 经纬度、高程、ECEF 与 ENU 之间的转换 | 坐标基准和坐标转换模块 |
| 把不同局部坐标系的向量自动旋转、平移到一起 | 业务数据准备模块 |
| 成果地图、报表、数据库和权限管理 | 上层应用系统 |
| 自动判定并删除某条观测 | 项目质量规则和人工审核流程 |

## 3. 能力总览

| 能力 | 面向客户的作用 | 适用说明 |
| --- | --- | --- |
| 三维 ENU 站网平差 | 统一计算全部站点坐标 | 适用于静态相对坐标网 |
| 精确控制点 | 把坐标成果固定到指定外部基准 | 适合已有稳定控制站的项目 |
| 随机控制点 | 使用带精度的控制坐标，同时允许其产生偏差 | 适合外部坐标本身有误差的项目 |
| 自由网平差 | 没有外部控制时保持站网内部几何关系 | 输出为内部基准坐标，不代表绝对位置 |
| 完整精度模型 | 同时考虑每条基线 E/N/U 之间的相关性 | 需要提供可信协方差 |
| 闭合与残差分析 | 判断观测是否与整体网络协调 | 支持成果审核和问题定位 |
| 异常影响抑制 | 降低粗差基线对最终成果的影响 | 结果仍需结合业务规则审核 |
| 分组精度校正 | 估计不同来源观测的整体精度倍率 | 需要组内有足够冗余 |
| 大型站网计算 | 在可控内存下处理更多站点 | 需要根据规模选择计算模式 |
| 结构化成果交换 | 便于接入现有平台和成果流程 | 输入输出字段稳定、便于序列化 |
| 可中断的长计算 | 便于服务端或批处理任务管理 | 适合规模较大的计算任务 |

## 4. 核心概念

| 概念 | 业务含义 |
| --- | --- |
| 站点 | 站网中的一个测量点，有唯一标识和可选名称 |
| ENU 坐标 | 以 East、North、Up 表示的三维坐标或向量 |
| 基线 | 从一个站点指向另一个站点的相对坐标向量 |
| 控制点 | 用于确定站网外部基准的已知坐标 |
| 坐标先验 | 带有精度范围的控制坐标，允许在平差后产生残差 |
| 固定站 | 被视为完全准确的控制坐标，不参与坐标改正 |
| 自由站 | 坐标由站网平差计算得到的站点 |
| 协方差 | 对观测不确定度和 E/N/U 相关性的完整描述 |
| 残差 | 原始观测与平差后理论值之间的差异 |
| 冗余度 | 一条观测被其他观测和约束检验的程度 |
| 单位权中误差 | 反映整体残差水平与输入精度是否匹配的指标 |
| 外部基准 | 由固定站或控制点提供的绝对坐标参考 |
| 自由网基准 | 在没有外部参考时为站网定义的内部原点 |

## 5. 输入要求

### 5.1 最小数据组成

一次站网平差至少需要：

1. 一组站点清单；
2. 一组站点之间的相对 ENU 基线；
3. 每条基线的 E/N/U 协方差；
4. 每个连通站网分量的外部基准，或明确选择自由网模式。

如果项目只有一个孤立站，且没有任何基线或控制坐标，无法从相对观测推导其位置，系统会拒绝该输入。

### 5.2 数据一致性要求

为了保证结果有实际测量意义，输入数据应满足：

- 所有站点和基线使用同一套 ENU 轴方向、同一原点定义和同一单位；
- `From=A, To=B` 明确表示向量为 `B - A`；
- 协方差填写的是方差和协方差，而不是标准差或权值；
- 协方差为有限、对称、正定的矩阵；
- 不同基线之间如果存在显著相关性，应在业务层评估其影响，因为本方案默认不同基线相互独立；
- 外部控制坐标若有明显不确定度，应作为随机控制点提供，而不是伪装成精确固定站。

### 5.3 固定控制点与随机控制点的选择

| 场景 | 推荐方式 | 原因 |
| --- | --- | --- |
| 坐标来自稳定、权威的项目基准 | 固定控制点 | 直接锁定外部基准 |
| 坐标来自另一套测量成果，有明确精度 | 随机控制点 | 允许不同成果之间通过平差协调 |
| 只关心站点之间的相对几何 | 自由网 | 不引入不可靠的外部坐标 |
| 同一站网有多个来源不同的控制成果 | 多个随机控制点 | 让系统根据精度共同估计 |

## 6. 处理原理

### 6.1 基本观测关系

每条基线都遵循同一个几何关系：

```text
观测基线 = 终点坐标 - 起点坐标 + 观测误差
```

因此，一条基线不单独决定一个站点的最终位置。系统会把所有相关基线和控制信息放在一起，寻找一组坐标，使整体残差在各自精度约束下最小。

### 6.2 为什么不是简单平均

不同基线的可靠程度通常不同：

- 精度高的基线应当对结果影响更大；
- 精度低的基线应当适当降低影响；
- E、N、U 之间可能存在相关性，不能简单把三个方向完全拆开；
- 闭合环中的多条观测会相互检验，单条观测不能脱离网络独立判断。

系统采用加权最小二乘思想：

```text
让所有残差的“按精度归一化后的总能量”最小
```

可以用下式概括：

```text
目标 = 残差ᵀ × 协方差的逆 × 残差
```

协方差越大，表示观测越不确定，该观测在总体目标中的影响越小；协方差越小，表示观测越可靠，该观测的约束越强。

### 6.3 整体处理流程

```mermaid
flowchart LR
    A["准备站点和基线"] --> B["统一坐标方向与单位"]
    B --> C["检查精度和网络连通性"]
    C --> D["确定外部或内部基准"]
    D --> E["按精度融合全部观测"]
    E --> F["计算统一站点坐标"]
    F --> G["计算残差、精度和质量指标"]
    G --> H["异常提示与成果审核"]
```

处理过程分为六个阶段：

1. **数据检查**：确认站点引用、方向、单位和协方差合法；
2. **网络分析**：识别相互连接的站网分量，检查是否有可用基准；
3. **建立基准**：使用固定控制、随机控制，或为自由网设置内部原点；
4. **整体平差**：让所有基线和控制信息共同参与计算；
5. **质量分析**：计算每条观测的残差、标准化残差、冗余度和整体指标；
6. **成果输出**：形成站点坐标、平差后基线、精度和告警信息。

## 7. 基准处理策略

### 7.1 外部基准模式

外部基准模式要求每个相互连通的站网分量至少有一个固定站或随机控制点。

优点：

- 输出坐标可以与项目外部坐标系统直接关联；
- 适合工程放样、控制网成果和跨项目坐标衔接；
- 不会因为缺少基准而产生任意平移。

如果某个分量没有外部基准，系统会明确报错，而不是返回看似正常但没有绝对意义的坐标。

### 7.2 自由网模式

只有相对基线、没有外部控制时，站网整体可以任意平移。自由网模式通过把每个无基准分量的 E、N、U 坐标质心设为零，定义一个稳定的内部原点。

自由网模式适合：

- 只关心站点之间的相对位置；
- 外部控制点暂时不可用，但需要先检查内部几何质量；
- 对多个相对测量成果进行内部一致性分析。

需要特别注意：

- 自由网坐标是内部坐标，不等于项目绝对坐标；
- 平移基准改变不会改变平差后基线和残差；
- 后续接入外部控制时，通常需要重新平差或进行基准转换。

### 7.3 混合站网

同一项目可以同时存在多个连通分量：

- 有固定站或控制点的分量使用外部基准；
- 没有外部基准但有相对观测的分量使用自由网内部基准；
- 两类分量互不强行平移，也不会被错误地当成一个整体。

## 8. 异常观测与精度管理

### 8.1 残差分析

平差后会把每条原始基线与由站点坐标反算出的理论基线进行比较：

```text
残差 = 原始基线 - 平差后基线
```

残差小并不自动代表观测可靠，仍需结合观测自身精度和网络冗余度判断。

### 8.2 主要质量指标

| 指标 | 它回答的问题 | 使用建议 |
| --- | --- | --- |
| 残差 | 这条观测与整体成果差了多少 | 先看绝对量级和方向 |
| 标准化残差 | 残差相对于自身精度是否偏大 | 用于比较不同精度观测 |
| 冗余度 | 这条观测是否能被网络中的其他信息检验 | 冗余度低时不能单凭残差下结论 |
| 坐标标准差 | 站点坐标的估计精度如何 | 用于成果发布和后续权重设置 |
| 单位权中误差 | 实际残差水平是否与输入精度匹配 | 结合整体检验使用 |
| 全局卡方检验 | 整体随机模型是否与观测表现相符 | 仅在固定随机模型条件下解释 |
| 条件性告警 | 网络是否存在数值上的弱几何或病态风险 | 需要结合站网结构复核 |
| 鲁棒权 | 某条基线是否被降低影响 | 是提示，不是自动剔除结论 |
| 精度倍率 | 某组数据的输入精度是否偏乐观或偏保守 | 大于 1 通常表示输入精度估计偏乐观 |

### 8.3 鲁棒处理

当个别基线可能含有粗差时，可以启用鲁棒平差。系统会根据一整条三维基线的综合偏离程度自动降低其影响，同时保留基线内部 E/N/U 的相关关系。

鲁棒处理的定位是：

- 防止少数异常观测过度拉动整体坐标；
- 为审核人员提供可疑基线提示；
- 在观测质量不均衡时提高成果稳定性。

鲁棒权小于 1 表示该基线被降权，但不等于系统已经证明该基线错误。是否重测、剔除或保留，应由项目质量规则和人工审核决定。

### 8.4 分组精度校正

如果不同设备、时段或解算策略的精度标定不完全一致，可以给基线设置数据组。系统根据每组观测的残差和有效冗余度，估计一个共同精度倍率：

- 倍率大于 1：该组实际波动大于输入估计，输入精度可能偏乐观；
- 倍率小于 1：该组实际波动小于输入估计，输入精度可能偏保守；
- 没有足够冗余时不强行估计，以避免产生没有统计意义的倍率。

## 9. 成果输出

### 9.1 站点成果

每个站点可获得：

- 最终 East、North、Up 坐标；
- 是否为固定控制点；
- 各方向标准差；
- 三维坐标协方差；
- 项目自定义名称和业务元数据。

固定站的坐标被视为精确基准，不会被平差改动；自由站的坐标和精度由整体网络决定。

### 9.2 基线成果

每条输入基线可获得：

- 原始观测向量；
- 根据平差坐标计算的理论向量；
- E/N/U 残差；
- 残差标准差和残差协方差；
- 标准化残差和冗余度；
- 鲁棒权及是否被降权；
- 所属数据组的精度倍率；
- 原始业务标识和元数据。

这使得成果审核可以从“最终坐标是否合理”追溯到“哪条观测对结果产生了什么影响”。

### 9.3 控制点成果

对于带精度的随机控制点，系统还会输出：

- 控制坐标的原始值和调整后值；
- 控制点残差；
- 控制点标准化残差和冗余度；
- 控制点残差精度。

这可以识别不同外部控制成果之间是否存在系统性偏差。

### 9.4 整体诊断

整体诊断包括：

- 站点、基线和控制点数量；
- 有效参数和自由度；
- 加权残差目标值；
- 单位权中误差；
- 求解收敛状态；
- 协方差和残差诊断是否可用；
- 基准类型及自由网分量数量；
- 全局检验结果；
- 非致命告警和使用建议。

当某类精度信息因计算模式被主动省略时，结果会明确标记“不可用”，不会让调用方把空值误认为零误差。

## 10. 计算规模与模式选择

### 10.1 常规规模

小型和中型站网通常适合直接计算模式，特点是：

- 结果稳定、流程简单；
- 可以直接获得完整站点间协方差；
- 适合控制网、工程项目和成果审核。

### 10.2 大型规模

当自由站数量增多、网络连接关系较稀疏时，可以选择迭代计算模式：

- 只利用实际相连站点形成的稀疏结构；
- 通过逐步逼近得到坐标；
- 使用按站点分组的局部精度信息加快收敛；
- 可根据项目需要减少完整协方差的内存占用。

### 10.3 精度输出取舍

| 输出策略 | 适合场景 | 代价 |
| --- | --- | --- |
| 完整精度 | 需要跨站相关性、完整审查和后续严密计算 | 内存和计算量较大 |
| 站点级精度 | 只需要每个站点精度和观测诊断 | 不保留完整跨站矩阵 |
| 基本成果 | 超大网络或处理中间轮次，只关心坐标和整体统计 | 不提供由协方差推导的局部指标 |

建议在项目方案阶段明确“成果发布需要哪些精度字段”，避免在超大网络中无必要地计算完整矩阵。

## 11. 典型业务场景

### 场景 A：有一个固定控制站的闭合网

**输入**：一个固定站、多个自由站、若干形成闭合环的基线。

**处理**：固定站提供外部基准，所有基线按精度共同平差。

**输出**：所有站点统一 ENU 坐标、闭合差分配结果、每条基线残差和整体检验。

适合工程控制网、施工测量和静态监测初始网。

### 场景 B：没有外部控制的相对网

**输入**：多个自由站和相互连接的相对基线。

**处理**：为每个连通分量建立零质心内部基准。

**输出**：内部相对坐标、网络闭合质量和观测异常提示。

适合前期内业检查、相对形变分析或等待外部控制成果期间的质量预审。

### 场景 C：多个设备或多个时段融合

**输入**：来自不同来源的基线，每条基线带有各自协方差，并按来源分组。

**处理**：先按输入精度加权，再按组估计必要的精度倍率。

**输出**：统一站点坐标、各来源对最终结果的影响、每组精度校正结果。

适合多接收机、多批次或多算法成果融合。

### 场景 D：存在疑似粗差

**输入**：网络中夹杂一条或少量可能异常的基线。

**处理**：启用鲁棒平差，对综合偏离较大的基线降低权重。

**输出**：稳定的整体坐标、可疑基线标识和降权程度。

适合自动化批处理，但最终剔除仍应由项目规则确认。

### 场景 E：大型稀疏站网

**输入**：站点数量较多、每个站点只与少量邻站相连的网络。

**处理**：选择稀疏迭代计算，并按实际成果需求选择精度输出级别。

**输出**：在可控资源下完成坐标和质量计算。

## 12. 系统集成边界

### 12.1 上游需要提供的内容

上游系统应负责：

- 生成或导入相对 ENU 基线；
- 把所有基线转换到共同坐标约定；
- 计算或提供可信的三维协方差；
- 标明基线方向、来源、时段和质量等级；
- 提供固定站或随机控制点信息；
- 按项目规则过滤明显无效或缺字段的数据。

### 12.2 平差能力负责的内容

本方案负责：

- 站网拓扑和基准完整性检查；
- 多基线、多控制信息的整体加权融合；
- 站点坐标和基线结果计算；
- 精度传播和质量指标计算；
- 可选的鲁棒处理和分组精度校正；
- 结构化错误、告警和成果输出。

### 12.3 下游可以使用的内容

下游系统可以据此实现：

- 坐标成果入库和版本管理；
- 基线闭合图、残差图和质量报表；
- 超限观测复核和重测任务派发；
- 控制网成果审批；
- 监测、施工或 GIS 业务的统一坐标输入。

## 13. 可靠性与成果解释原则

### 13.1 结果质量取决于输入随机模型

平差不会自动创造观测精度。若协方差过小、过大或方向相关性缺失，结果可能在数学上收敛，但统计解释不可靠。因此项目交付时应同时审核：

- 基线向量是否使用共同坐标系；
- 协方差是否来自实际解算精度；
- 不同来源的精度是否处于同一量纲；
- 外部控制点是否被正确区分为“精确”或“有误差”。

### 13.2 收敛不等于合格

计算成功只说明找到了一个数值解，不代表：

- 所有观测都没有粗差；
- 输入精度模型正确；
- 外部控制坐标没有系统偏差；
- 站网几何足够强；
- 成果满足项目验收阈值。

成果验收应同时检查坐标精度、残差、冗余度、全局检验和业务容差。

### 13.3 鲁棒标记不等于自动剔除

被降权的基线可能是粗差，也可能是输入精度低、网络几何导致的相对弱观测。建议将“降权”作为审核线索，而不是直接作为删除指令。

### 13.4 自由网成果不应当作绝对坐标发布

自由网坐标适合内部比较和几何检查。若需要对外发布绝对坐标，必须补充可靠外部控制或在业务层完成明确的基准转换。

## 14. 交付与验收建议

### 14.1 功能验收

建议至少准备以下验收数据集：

1. **已知小型闭合网**：验证坐标、闭合差和精度传播；
2. **非零控制点网**：验证外部坐标基准不会被错误归零；
3. **带误差控制点网**：验证控制点可以产生残差并参与协调；
4. **无控制自由网**：验证内部坐标和相对基线保持正确；
5. **多连通分量**：验证各分量的基准判断互不干扰；
6. **含疑似粗差网**：验证异常提示、降权和审核信息；
7. **多来源精度网**：验证分组精度倍率和结果解释。

### 14.2 质量验收

验收指标应由项目根据测量等级和应用场景制定，通常包括：

- 站点坐标与权威参考成果的差异；
- 基线残差及闭合差是否满足限差；
- 坐标标准差是否满足发布要求；
- 标准化残差是否存在明显超限；
- 低冗余观测是否被单独标识；
- 整体随机模型检验是否通过；
- 计算告警是否有明确处理结论；
- 不同计算模式下的结果差异是否在容差内。

### 14.3 性能验收

性能应使用项目实际规模和典型拓扑测试，不建议只用站点数量作为唯一指标。至少应记录：

- 站点数、基线数和连通分量数；
- 坐标求解耗时；
- 精度和残差后处理耗时；
- 峰值内存；
- 启用鲁棒或分组精度估计后的额外耗时；
- 任务取消和失败重试行为。

## 15. 常见问题

### Q1：它能替代 RTK 或 PPP 解算吗？

不能。它使用的是已经解算好的相对 ENU 结果，负责站网整体协调和质量分析，不负责卫星观测层的定位解算。

### Q2：必须提供固定站吗？

不一定。如果只需要内部相对坐标，可以使用自由网模式；如果需要绝对坐标，则每个相关分量应至少有可靠固定站或随机控制点。

### Q3：没有协方差还能计算吗？

不建议。协方差是加权平差和精度评定的基础。若暂时只能提供对角精度，应明确这是近似随机模型，并在成果审核中降低解释强度。

### Q4：随机控制点和固定站有什么实际区别？

固定站被视为完全准确，结果不会反过来检验它；随机控制点带有精度范围，系统可以在多个控制信息之间协调，并报告控制点残差。

### Q5：自由网输出的坐标能直接上图或发布吗？

可以用于内部相对展示和几何分析，但不能直接当作外部绝对坐标发布。发布前需要接入外部基准。

### Q6：出现大残差时系统会自动删除观测吗？

不会。系统可以提供标准化残差、冗余度和鲁棒权作为审核依据，是否重测或剔除由项目质量流程决定。

### Q7：为什么整体检验有时没有结果？

当启用了根据当前数据自适应调整权值或精度倍率时，固定随机模型的卡方检验前提已经改变，系统会主动省略该检验，并在诊断信息中说明原因。

### Q8：不同基线之间有相关性时怎么办？

当前方案完整处理单条基线内部 E/N/U 相关性，但默认不同基线之间相互独立。若跨基线相关性不可忽略，需要在数据准备和方案评估阶段单独处理。

## 16. 总结

`nav-adjust-go-lib` 的核心价值不是单独计算一条新坐标，而是把多个相对定位成果放到同一个可解释的整体模型中，得到：

- 统一基准下的站点坐标；
- 按观测精度协调后的平差基线；
- 可追溯的坐标和观测精度；
- 可用于审核的残差、冗余度和整体质量结论；
- 对粗差和来源精度差异的可控处理。

对于客户项目，最重要的前置条件是：**坐标方向统一、协方差可信、基准定义清楚、验收阈值明确**。满足这些条件后，该方案可以作为站网成果计算和质量控制的核心能力，嵌入现有 GNSS、测量、监测或工程管理系统中。
